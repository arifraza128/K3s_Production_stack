# ADR 005: AWS S3 (`ap-south-1`) vs Backblaze B2 for Off-Cluster DR Backups

- **Status:** Accepted
- **Date:** 2026-11-08
- **Evidence Link:** [`terraform/bootstrap/main.tf`](../../terraform/bootstrap/main.tf) · [`docs/evidence/dr-drill/scorecard.md`](../evidence/dr-drill/scorecard.md)

## Context
Phase 8 requires durable, encrypted off-cluster object storage for Velero Kubernetes backups, Gitea PostgreSQL `pg_dump` archives, and the Sealed Secrets master key so backups survive `terraform destroy` of the `platform` compute stack.

## Decision
Provision a versioned, AES-256 encrypted **AWS S3 bucket** (`phoenix-backups-ap-south-1-arifraza128`) with a 30-day lifecycle policy in [`terraform/bootstrap/main.tf`](../../terraform/bootstrap/main.tf) (`prevent_destroy = true`), accessed via least-privilege EC2 IAM Instance Profile (`phoenix-k3s-node-profile`).

## Alternatives Considered
1. **Backblaze B2:** S3-compatible and cheaper per GB (`$0.006/GB`), but requires static long-lived application keys stored in Kubernetes secrets and incurs cross-provider internet transfer latency.
2. **Local EBS Snapshots Only:** Coupled to AWS EC2 volume lifecycle; harder to inspect individual `pg_dump` SQL archives or `sealed-secrets` master key YAML files during partial corruption drills.

## Consequences
- ✅ **Zero static AWS keys in cluster:** EC2 instance authenticates via IAM Instance Profile restricted strictly to the backup bucket ARN ([`terraform/bootstrap/main.tf`](../../terraform/bootstrap/main.tf)).
- ✅ **Same-region speed & zero data-transfer fees:** EC2 and S3 are both in `ap-south-1` (Mumbai), enabling `11s–15s` RTO and `1s` RPO ([`scorecard.md`](../evidence/dr-drill/scorecard.md)).
- ❌ **Slightly higher storage rate (`$0.023/GB-mo`):** At `< 5 GB` of backups, total S3 cost is `~$0.12/month` ([`cost.md`](../cost.md)).
